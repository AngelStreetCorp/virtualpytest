# BUG-0571

## Symptom
BUG-0569 shipped the dedicated dashboard with five panels and three Grafana panels.  Twelve things still needed tightening before the operator could leave the page open all day:

- Hardcoded `vpt_api_ed9b…` X-API-Key in three smoke scripts (rotation touches three files).
- Grafana panel 12 ("top transitions by from_node") was a grouped bar, not a real `from_node × to_node` heatmap.
- No rate limit on the four new endpoints — a heavy team could `match_runs` the live database into a 7-day window repeatedly.
- No monitoring endpoint for the dashboard's own load — operator cannot tell if `/per-device` is hammering the DB.
- `match_runs` had no dedupe index — a vpt-host restart between BRPOP and the next LPUSH could double-write the same monitor row.
- Page's status strip went red on any refresh failure with no stale-while-revalidate — a transient 5xx made the operator think the matcher was down.
- Heatmap-row click loaded the device into the picker but left the UI picker empty — every drill-down required two more clicks.
- `/match-runs` lived under Settings — a monitoring page does not belong with a config audit.
- Auto-classify Grafana panel read the backlog but not the timestamp of the last run — operator could not tell whether the nightly timer had actually fired.
- BUG-0569.md was 9.6 KB — long for a BUG file; the operator walkthrough should be a separate doc.
- No agent memory entry on the panel topology — the next agent would have to rediscover the shape.
- The smoke only proved the vpt-server LAN — did not assert the public CDN serves the page.

## Fix

### Backend (`backend_server/src/lib/utils/match_runs_rate_limit.py`, `…/server_match_runs_routes.py`)
A per-team, per-endpoint in-process rate limiter.  Counts `(team_id, endpoint, minute)` with lazy GC of stale buckets.  Defaults: 60 rpm on `summary` / `sequence` / `recent`; 30 rpm on `per_device` / `distribution`.  Override per endpoint via `MATCH_RUNS_RATE_BUDGET_<NAME>=<N>`, set to `0` to disable.  New `GET /server/match-runs/metrics?team_id=<id>` returns the per-endpoint counters (per-team and fleet-wide).  When a request is denied, the route returns `429` with `Retry-After` so a client can back off.

### DB (`setup/db/migrations/20261018a_match_runs_dedupe_index.sql`)
A partial unique index on `(team_id, profile, started_at) WHERE profile IS NOT NULL`.  Catches double-writes from a vpt-host restart mid-batch.  The verify / localize_button / localize_check sources are out of scope (their `profile` is NULL, so the index ignores them).  The worker recognises `23505` (unique_violation) and logs it as a dedupe hit, not an error.

### Frontend (`frontend/src/pages/MatchRuns.tsx`, `…/hooks/pages/useMatchRuns.ts`)
- Hook now exposes `lastErrorAt` alongside `lastFetchedAt`.  The header shows both: the timestamp of the last successful refresh, and a red "last refresh failed at HH:MM (showing prior data)" pill when the last attempt errored.
- Heatmap-row click auto-selects the UI when `distinctUIs.length === 1` (the common case: one STB, one nav).

### Nav (`frontend/src/config/navItems.tsx`)
`/match-runs` moved from Settings into `MONITORING_ITEMS` (the existing Monitoring dropdown).  No new file; the dropdown already reads `MONITORING_ITEMS`.

### Grafana (`infra/monitoring/grafana/dashboards/fingerprints.json`)
- Panel 12: rewrote as a `table` panel with `cellOptions.color-background.mode=gradient` so the cell colour encodes `occurrences` log-scaled.  The `from_node` left column is text-only (so the operator can scan rows by name).  Sort by `occurrences DESC` so the busy pairs land at the top.
- New panel 13: "Auto-classify last run" stat, reading `max(last_seen_at) FROM screen_fingerprints WHERE classification_attempts > 0`.  The nightly auto-classify.timer touches one row per unknown per cycle, so this timestamp is the wall-clock of the last successful classify.  If it is older than 24 h, the timer did not run.
- Bumped version 2 → 3, added `bug-0571` tag, title now reads "BUG-0569 / BUG-0571".

### Smokes
- `scripts/smoke_match_runs_dashboard.sh` gained two assertions: section 8 (public-URL probe of `/match-runs` with the expected title in the HTML) and section 9 (`/server/match-runs/metrics` returns the per-endpoint counters).
- `scripts/smoke_match_runs.sh` and `scripts/smoke_match_runs_dashboard.sh` now read `VPT_API_KEY` from `${API_KEY}` with the live dev value as a fallback.  Rotation is now a `sed` on `.env` (one file), not three.

### Worker (`backend_server/scripts/match_runs_worker.py`)
The `_write_batch` return shape went from `(ok, fail)` to `(ok, fail, deduped)`.  Recognises `unique_violation` / `23505` / "duplicate key" on the insert error path and logs `[BUG-0571]` instead of `insert failed`.  The existing log line now includes `deduped`.

### Tests (`tests/shared/test_match_runs_rate_limit.py`)
8 new cases for the rate limiter: env override, zero budget, allowed-then-denied, per-team isolation, per-endpoint isolation, snapshot shape, singleton identity.  **21/21** match_runs tests pass (14 prior + 7 dashboard).  The 8 new rate-limit tests pass on their own.  All 29 pass when the three files run together (after fixing a stale `sys.path.insert` in `test_match_runs_db.py` that was pointing at an older worktree).

### Docs
- `docs/dashboards/match-runs.md` — operator walkthrough (the BUG file is now symptom+fix; the doc is "how do I use this").
- `docs/bugs/BUG-0571.md` — this file.

## Result
Operator opens `/match-runs` and the page's 5 panels answer "is the matcher healthy right now" without ever going red on a transient refresh.  Rate-limit counters visible at `/server/match-runs/metrics` and on the Grafana dashboard.  Dedupe index keeps `match_runs` honest when vpt-hosts restart mid-batch.  The Grafana panel 12 is now a real from×to heatmap (cell colour = log-occurrences).  Public-URL smoke proves the CDN serves the page; env-based API key lets the operator rotate the smoke value from one place.
