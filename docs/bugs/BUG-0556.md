# BUG-0556

## Symptom
Three things were true before:

1. When a verify_node failed, the operator could see the failure but not what the runner-up was. The Localize button showed one node and forgot the rest of the candidate list. The monitor's per-frame matcher verdict lived only in JSON files on the host.
2. Unknown screens that the matcher kept seeing were invisible until the operator manually ran `unknown_screen_scan.py --apply` over the capture archive — a manual one-shot that the existing handover flagged as "the list is dominated by broadcast frames" and "the content filter is not good enough".
3. There was no per-node "how many times was this node verified?" counter, no last-verified timestamp, and no transition matrix to feed prediction.

## Fix
TASK-115, end-to-end. Four pieces:

**Storage (migrations 20261016a/b/c)**
- `public.match_runs` — one row per matcher run. Top-3 candidates JSONB + 6 mirror columns for SQL-friendly analytics. Self-FK chain on `previous_event_id` with denormalised `previous_node_id`, `step_in_session`, `session_id`. Three views: `v_node_transitions` (P(to_node | from_node)), `v_uncertain_hits` (margin < 5%), `v_recent_sequence` (last 20 events per device).
- `public.screen_fingerprints.classification_attempts` — counter so the AI gives up after 3 failed propose-name calls.
- `prune_screen_fingerprints_noise(uuid, int, int, int)` — Postgres function, called by RPC, that drops the noise on the "big counter" rule (3 hits in 14 days, never below the top-500).

**Writers (host + button)**
- `execute_single_node_verification` records one match_runs row per verify from the localize_check payload.
- `POST /api/host/localize` records one match_runs row per button press.
- `POST /api/host/match_run` is the bridge for the future vpt-monitor-img writer.
- All three bump `screen_fingerprints.seen_count` for unknown / low_confidence hits via a new `screen_fingerprints_bump.bump_unknown_screen` helper.

**Auto-classify (the missing scheduler)**
- `backend_server/scripts/auto_classify_unknowns.py` — picks rows that crossed `seen_count >= 5` AND `classification_attempts < 3`, hands them to `vision.dom` (the existing `unknown_screen_scan.classify_with_vision_dom` is the one source of truth), and upserts into `userinterface_unknown_screens` so the operator's existing /configuration/interface/.../unknown page shows the proposed name.
- `auto-classify.service` + `auto-classify.timer` — nightly at 02:00 via systemd, observable via `systemctl list-timers`.

**Surface**
- 3 new entries in the analytics catalog: `match_runs`, `node_transitions`, `screen_fingerprints_counter`.
- `infra/monitoring/grafana/dashboards/fingerprints.json` — 5 stat panels + 4 tables (verdict distribution, top transitions, uncertain hits, recent runs).
- `frontend/src/pages/MatchRuns.tsx` — 3 tabs (Recent / Uncertain / Transitions) on the same MUI primitives as the rest of the operator UI.

**Smoke (`scripts/smoke_match_runs.sh`)**
- 10 checks in <60s: table exists, views exist, prune fn exists, classification_attempts column present, server route 200, host route registered, systemd timer scheduled, scheduler --dry-run runs, Grafana JSON parses, live match_runs rows present.
