# VirtualPyTest Services

This directory contains system service configurations for running VirtualPyTest components as background services on different platforms.

## Linux Services (`linux/`)

### `vpt-server.service`
**Purpose**: Runs the main VirtualPyTest Flask backend server
- **Executes**: `src/app.py` - The main Flask application server
- **Port**: 5109 (default)
- **Function**: Handles all API endpoints, manages hosts/devices, serves the web interface
- **Restart**: Automatic restart on failure with 10-second delay

### `vpt-heatmap.service`
**Purpose**: Continuous background heatmap generation
- **Executes**: `scripts/heatmap_processor.py` - Background processor for heatmap mosaics
- **Function**: Every minute fetches latest images from all hosts/devices, creates composite heatmap mosaics, and uploads to cloud storage (R2)
- **Features**:
  - Generates full mosaics + separate OK/KO device mosaics
  - Creates analysis JSON with incident detection (blackscreen, freeze, no audio)
  - Uses 24-hour circular buffer with HHMM naming (1440 files)
  - Parallel image processing for performance
- **Restart**: Automatic restart on failure with 30-second delay

### `vpt-discard-scripts.service`
**Purpose**: Continuous background analyzer worker for script discard/false-positive decisions
- **Executes**: `scripts/discard_worker.py` - starts Sherlock (`analyzer`) background queue processor
- **Function**: Consumes `p2_scripts` Redis queue and writes `checked/discard/discard_comment` updates
- **Requires**:
  - `REDIS_URL` (or local Redis config)
  - `OPENROUTER_API_KEY` (for direct LLM classification mode)
- **Restart**: Automatic restart on failure with 10-second delay

### `vpt-discard-incidents.service`
**Purpose**: Continuous background analyzer worker for incident discard/false-positive decisions
- **Executes**: `scripts/discard_worker.py` - starts Sherlock (`analyzer`) background queue processor
- **Function**: Tracks incident discard flow using the same analyzer worker runtime
- **Requires**:
  - `REDIS_URL` (or local Redis config)
  - `OPENROUTER_API_KEY` (for direct LLM classification mode)
- **Restart**: Automatic restart on failure with 10-second delay

## macOS Services (`mac/`)

### `com.virtualpytest.server.plist`
**Purpose**: Launches the complete VirtualPyTest system
- **Executes**: `scripts/launch_virtualpytest.sh` → delegates to `setup/local/linux/launch_core.sh`
- **Function**: Starts all core components (backend_server, backend_host, frontend) in sequence
- **Launch**: Runs at system startup and keeps alive

## Service Management

### Linux (systemd)
```bash
# Enable/start services
sudo systemctl enable vpt-server.service
sudo systemctl start vpt-server.service

sudo systemctl enable vpt-heatmap.service
sudo systemctl start vpt-heatmap.service

sudo systemctl enable vpt-discard-scripts.service
sudo systemctl start vpt-discard-scripts.service

sudo systemctl enable vpt-discard-incidents.service
sudo systemctl start vpt-discard-incidents.service

# Check status
sudo systemctl status vpt-server.service
sudo systemctl status vpt-heatmap.service
sudo systemctl status vpt-discard-scripts.service
sudo systemctl status vpt-discard-incidents.service

# View logs
sudo journalctl -u vpt-server.service -f
sudo journalctl -u vpt-heatmap.service -f
sudo journalctl -u vpt-discard-scripts.service -f
sudo journalctl -u vpt-discard-incidents.service -f
```

### macOS (launchd)
```bash
# Load/start service
sudo launchctl load /Library/LaunchDaemons/com.virtualpytest.server.plist
sudo launchctl start com.virtualpytest.server

# Check status
sudo launchctl list | grep virtualpytest

# View logs (configured in plist)
tail -f /tmp/server.log
```

## Notes
- These are template files with `%USER%`, `%PROJECT_ROOT%` placeholders
- Actual service files are generated by setup scripts with correct paths
- Services run under the specified user account with restricted privileges
- All services include security hardening (NoNewPrivileges, restricted paths)
